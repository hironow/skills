# スキルの実験 009: 停止をまたぐ途中の約束がない題材で、「なし」と書けるか

## 問い

実験 008 で、停止をまたぐ途中の約束がある題材では、スキルがその場面を拾うことを確かめた。
逆の道はまだ実際の実行で試していない。
途中の約束がない題材で、スキルが停止の場面を作り出さず、README に理由つきで `<!-- stop-scene: none; <理由> -->` と書けるかを確かめる。

## やり方

1. 題材は、社内向けの商品カタログの閲覧サイトにする。
   毎朝、基幹システムから CSV を取り込んで商品と価格を表示するだけで、注文、在庫の引き当て、外部への送信はない。
   取り込みは何度やり直しても同じ結果になる。
   依頼文には「停止」「緊急」「メンテナンス」の語を入れない。
   スキルの名前は出さない。
2. Sonnet 5.5 のサブエージェントに、スキルの写し（実験 008 と 009 の記録を除く）と、空の作業フォルダだけを渡す。1 回だけ実行する。
3. 作業フォルダで `just check` と `evals/grade.py` を実行する。README と検査モデルを読んで、次を記録する。
   - 停止をまたぐ途中の約束を、どう判断したか。
   - `stop-scene: none;` の行を理由つきで書いたか。それとも停止の場面を検査モデルにしたか。
   - 検査モデルにした場合、その「途中のもの」が外部への約束か、内部の処理（取り込みの途中など）か。
   - 存在しない役割を作り出したか。

## 実行前の予想

- 停止の場面は作り出さず、`stop-scene: none;` の行を理由つきで書く。理由は「取り込みはやり直せば同じ結果になり、外部に約束しているものがない」。
- ただし、取り込みの途中で止まると、古い価格と新しい価格が混ざって見える、という内部の整合を検査モデルにする可能性は残る。これは停止をまたぐ外部への約束ではないので、判定では区別して記録する。
- `just check` は 0、`status.py` の停止の項目は done、採点の停止の項目は合格。

## 判定の規則

- 成功: `just check` が 0、README に理由つきの `stop-scene: none;` があり、採点の停止の項目が合格、作り出した役割がない。
- 部分的な成功: 「なし」とは書かず、内部の処理の途中を停止の場面として検査モデルにした。外部への約束を作り出していなければ、スキルの誤りとはしない。ただし、スキルの言葉が「内部の処理」と「外部への約束」を区別できているかを結果で検討する。
- 失敗: 外部への約束を作り出した、または `just check` が 0 でない、または停止の項目が通らない。

## 限界

- 題材 1 つ、実行 1 回である。
- 題材は「なし」になりやすいものを私が選んだ。境界の題材ではない。
