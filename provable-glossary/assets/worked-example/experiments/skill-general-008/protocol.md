# スキルの実験 008: 売る・予約する以外の業務でも、停止の場面を正しく扱えるか

## 問い

スキル `provable-glossary` は、段階 1 で「緊急停止の場面」を必須にしていた。
これを「停止をまたぐ途中の約束」に言い換え、途中の約束がない題材では、理由を書けば「なし」で通れるように変える。
これまでスキルを試した題材は、どれも売る・予約する・割り当てる業務だった。
それ以外の業務で、変えたスキルが次の 2 つを満たすかを確かめる。

1. 停止をまたぐ途中の約束があるなら、それを見つけて検査モデルにする。
2. 存在しない役割（資源、決済など）を作り出さず、「なし」と書く。

## やり方

1. スキルを変え、`just check` が通る状態でコミットする。
2. 題材は社内の稟議（りんぎ）の承認ワークフローにする。
   申請者が申請し、上長と経理が順に承認し、承認が済むと外部の会計システムへ支払いの依頼が送られる。
   承認には期限がある。
   依頼文には「停止」「緊急」「メンテナンス」の語を入れない。
   スキルの名前は出さず、スキルの説明に合うふつうの依頼として書く。
3. Sonnet 5.5 のサブエージェントに、スキルのフォルダと空の作業フォルダだけを渡す。
   このリポジトリの実例や記録を読ませない。
   1 回だけ実行する。
4. 作業フォルダで `evals/grade.py` を実行し、停止の項目の結果を記録する。
   あわせて、作業フォルダの README の役割の表と、検査モデルを読んで、次を記録する。
   - 停止をまたぐ途中の約束を挙げたか。挙げたなら何か。
   - 検査モデルにしたか、「なし」と書いたか。
   - 存在しない役割を作り出したか。
   - 到達した段階と、`just check` の終了コード。

## 実行前の予想

- 依頼に停止の語がなくても、スキルの手順 0 の問いから、停止の場面を拾う。
  途中の約束として、外部の会計システムへの支払いの依頼（送ったが結果が返っていない）を挙げ、検査モデルにする。
  「なし」とは書かない。
- 資源と振替は「なし」にする。決済は、会計システムへの依頼に読み替える。
- 段階 1 に到達し、`just check` は 0 で終わる。段階 2 まで進むかは半々と見る。

## 判定の規則

- 成功: `just check` が 0、停止の項目が通る（検査モデルにしたか、理由つきで「なし」と書いた）、作り出した役割がない。
- 失敗: 上のどれかが欠ける。失敗した項目と原因（スキルの書き方か、モデルの力か）を結果に書く。
- 予想が外れたら、そのまま書く。

## 限界

- 題材は 1 つ、実行は 1 回である。言い換えが一般に働くことの証明にはならない。
- 依頼文は私が書いた。停止の場面を拾いやすい題材を選んでいる可能性がある。
