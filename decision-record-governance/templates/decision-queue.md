# 決めてほしいこと一覧（Decision Queue）

> **これは何**: 未承認の決定記録（ADR / PDR）を「誰が・何を・いつ決めるか」で一覧にしたもの。エンジニアでなくても読めるよう平易に書く。各項目の詳細は右端の元ファイルを参照。
> **記載ルール**: 決定記録のガバナンス ADR（例: ADR 0029）に準拠。**作者がいる項目は「作者連絡先」列の安定したhandle（GitHub `@handle`またはSlack `<@UXXXXXXXX>`など）が必須**。
> **状態の意味**: 早見表はすべて `Proposed`（提案中＝未承認）。決まると `Accepted` / `Rejected` / `Deferred` のいずれかになり、行を下の「決定済みログ」へ移す。`Accepted` と `Rejected` の記録本文は書き換えず「覆すときは新しい記録で supersede（置き換え）」する。`Deferred` は再検討条件つきの保留で、再検討するときは新しい `Proposed` 記録を起票する。

---

## 0. 使い方（決裁の進め方）

1. 下の「早見表」で全体像をつかむ。
2. **ADR（技術）** は推奨案どおり Accept でよいか確認 → 各 ADR 末尾の「決定（記入待ち）」にチェック＋決定者名＋日付を記入。
3. **PDR（プロダクト/UX）** は中立に選択肢を並べてあるので、プロダクト責任者が選ぶ → 各 PDR 末尾の「決定（記入待ち）」に記入。
4. 決裁は各行の「相談記録」で依頼・催促・確定報告を行う（GitHub thread、Slack thread、または承認済みのdurable venueが会話ログ）。
5. 決まったら行を「決定済みログ」へ移し、記録ファイルと README を更新する。
